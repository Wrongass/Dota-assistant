# 0004. Развёртывание на сервере

Дата: 2026-10-14. Статус: принято. 2026-10-16: сайт развёрнут на сервере и работает с входом по паролю, но пока по HTTP
без HTTPS. Доработки после развёртывания — [замечания](../reviews/2026-10-16-deploy-review.md).

## Контекст

Сайтом должна пользоваться вся команда, в том числе с телефонов во время драфта. Сервер арендуем вместе с другом;
сейчас на нём закрыты все TCP-порты (доступ, вероятно, только через VPN друга). VPN команде неудобен.

## Решения

- **Доступ — по общему паролю команды**, без VPN. Пароль — переменная окружения `SITE_PASSWORD`; после входа
  подписанная HMAC cookie на 30 дней (HttpOnly, SameSite=Lax, Secure за HTTPS). Не больше 5 неверных попыток
  в минуту с адреса. Без `SITE_PASSWORD` (локальный запуск) вход не нужен; в docker-compose он обязателен.
- **Только HTTPS.** Пароль по HTTP уходил бы открытым текстом. Caddy в docker-compose (профиль `https`) сам
  получает сертификат Let's Encrypt — нужен домен с A-записью на сервер. Если у друга уже есть обратный прокси
  на 80/443, Caddy не запускаем, а добавляем в его прокси правило на `127.0.0.1:8070`.
- **Сайт наружу напрямую не публикуется**: контейнер слушает только `127.0.0.1:8070`, снаружи — только прокси.
- **Сборка образа — на сервере** (`git pull` + `docker compose build`) на старте. Когда заработает, можно перейти
  на сборку в GitHub Actions → GitHub Container Registry, чтобы не нагружать общий сервер.
- **Данные качаются на сервере**: `deploy/update-data.sh` по cron раз в сутки (≈140 запросов из 3000 в день)
  и вручную перед игрой; после обновления сайт перезапускается (загрузка данных ≈ 1 с).
- **Конфиг и ручные планы — в git** (`config/players.yaml`, `analysis/**/*_plan.md`): правим локально, пушим,
  на сервере `git pull`.
- **`/health`** — без входа, для проверки, что сайт жив.

## Открытые вопросы (к другу / при первом входе на сервер)

1. Как попасть на сервер (VPN/SSH-порт), есть ли у нас пользователь с правом запускать Docker.
2. Установлены ли Docker и Docker Compose; ОС.
3. Заняты ли порты 80/443, есть ли обратный прокси.
4. Свободно ли ≥ 512 МБ RAM и ≥ 1 ГБ диска.
5. Домен: есть ли свой; если нет — бесплатный поддомен (например DuckDNS) или покупка.
6. Репозиторий `Wrongass/test2` приватный? Тогда на сервер нужен deploy key (только чтение).

## Последствия

- Риск утечки пароля: один общий пароль. Смена `SITE_PASSWORD` разлогинивает всех.
- Каждое обновление кода — пересборка образа на сервере (2–4 минуты) или переход на GitHub Actions.
