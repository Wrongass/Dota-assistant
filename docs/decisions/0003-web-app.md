Дата: 2026-10-14. Статус: принято. Предложение и user stories — [docs/proposals/web-mvp.md](../proposals/web-mvp.md).

## Решения по вопросам

| Вопрос | Ответ |

| Бэкенд | Java (тот же Gradle-проект) |
| Фронтенд | на выбор разработчика — см. ниже |

## Стек

- **Javalin 6.7** — лёгкий HTTP-сервер на Java: одна зависимость, старт за доли секунды, без магии Spring.
  Ветка 7.x свежее, но меняет API конфигурации; 6.x стабильна и хорошо известна.
- **JTE 3** — серверные шаблоны с проверкой типов при сборке (плагин `gg.jte.gradle` прекомпилирует шаблоны в
  классы). Ошибка в шаблоне ломает `./gradlew build`, а не страницу во время игры.
- **Ванильный JS** только на странице драфта: поиск героя, ввод ходов, запрос `POST /api/draft` → JSON.
  Ни Node, ни сборки фронтенда, ни CDN: всё отдаётся с локального сервера, сайт работает без интернета.
- **commonmark-java** (+ таблицы GFM) — показ ручных `draft_plan.md` / `game_plan.md`.
- **Docker**: многоэтапный образ (сборка Gradle → JRE 21), `data/` и `config/` монтируются томами.

## Архитектура

- `dota.analysis` — расчёт: `Meta`, `PlayerStats`, `League`, `Scoring` + **view-модели** (records) для каждого
  отчёта. `Analyze` больше не считает и не форматирует одновременно: он собирает view-модели и отдаёт их
  `MarkdownRenderer`. Вывод `./gradlew analyze` не меняется — это проверяет эталонный тест.
- `dota.analysis.AnalysisContext` — однократная загрузка всего из `data/` + `config/` (≈1 с); её используют
  и генератор, и сайт («Перечитать данные» — без перезапуска).
- `dota.analysis.DraftEngine` — состояние драфта → советы (в том же пакете, что `Meta` и `PlayerStats`: им не нужен публичный API). Чистая логика, юнит-тесты, `DraftBacktest` по матчам лиги.
- `dota.web` — Javalin + JTE: страницы читают те же view-модели. К OpenDota сайт не обращается.

## Следствия

- Новая команда `./gradlew web` (порт 7070, только 127.0.0.1 по умолчанию; `--host 0.0.0.0` в Docker).
- Сервер для команды позже: тот же образ, нужен будет хотя бы пароль — не в MVP.
