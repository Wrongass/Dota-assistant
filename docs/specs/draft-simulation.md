# Симуляция драфта против соперника

Статус: черновик, ждёт подтверждения пользователя (1.11.2026).

## 1. Что нужно

Капитан тренирует драфт Captains Mode против конкретной команды. Баны и пики нашей команды делает он, баны и пики
соперника делает сайт. Соперник драфтит осмысленно: от игроков этой команды и их героев, с учётом линий, синергии,
пересечения пулов и контрпиков на последних пиках. После драфта сайт подробно оценивает, чей драфт сильнее.

Сверх этого ничего не добавляем: без сохранения симуляций, без сравнения сценариев, без статистики по прошлым
симуляциям.

## 2. Решения пользователя (1.11)

| Вопрос | Решение |
|---|---|
| Откуда свойства героев (иллюзии, пуш, Рошан, файт, сплит, кайт) | Справочник `config/hero_traits.yaml`, заполняет агент на всех героев патча, пользователь может править |
| Бот всегда делает один лучший ход или выбирает | Выбирает из 2–3 лучших ходов с близкой оценкой, слабых ходов не делает |
| Ручные позиции | Наши правятся в любой момент. Позиции соперника во время драфта — наш прогноз, бот держит свой план скрыто и раскрывает в конце. После конца можно править обе команды, оценка пересчитывается сразу |
| Подсказки «Нам банить / брать» в симуляции | Показываются, галочка «без подсказок» их скрывает |

## 3. Как это выглядит

- На странице драфта переключатель режима: «Вручную» (как сейчас) и «Симуляция». Соперник выбирается там же, где сейчас.
  Составы обеих команд берутся из «Состава на игру», то есть с учётом сохранённых замен.
- В симуляции ввод доступен только на наших ходах. На ходу соперника поиск отключён, через 0,5–1 секунды сайт сам
  вносит бан или пик соперника и переходит дальше. Если подряд два хода соперника, они вносятся по очереди.
- «Отменить» (и Ctrl+Z) откатывает к состоянию перед нашим последним ходом: вместе с ним уходят ответы соперника после
  него. Исправление старого хода по клику на ленту в симуляции отключено, только отмена.
- «Пропустить ход» за нас работает как в CM (пропущенный бан). Бот ходы не пропускает.
- Галочка «без подсказок» скрывает панели советов (Нам банить, Нам брать, их вероятные пики и баны). Лента, слоты и
  позиции остаются.
- «Сбросить» начинает новую симуляцию с новым случайным зерном. Зерно хранится в адресе, поэтому обновление страницы
  не меняет уже сделанные ходы бота.

## 4. Как решает соперник

Бот использует тот же `DraftEngine`, только смотрит с их стороны: `advise(их состав, наш состав, …)`. Отсюда уже
готовы оценки «они берут» и «они банят»: умение и доля игр игрока на герое, турнирные пики, линия по STRATZ против
наших лейнеров, контрпики и синергия по мете. Поверх добавляются правила из требований.

### 4.1. Кандидаты

- Пик: только герои, на которых их свободный игрок реально играет (правило `plays()`: 3+ игры, пик в турнире или
  недавние игры), и только на позиции, где этот игрок стоит. Наугад из пула бот не берёт.
- Бан: любой доступный герой.

### 4.2. Ценность пика

`ценность(h) = комфорт игрока + линия против наших + преимущество по игре против наших пиков + синергия со своими +
поздняя игра`.

- Комфорт: сглаженный винрейт и доля игр игрока на герое, турнирные пики (как в прогнозе их пиков сейчас).
- Линия: исход линии по STRATZ против наших героев на встречных позициях. Пока наши позиции неизвестны, против
  вероятных.
- Синергия «в том числе в лейте»: синергия пары по мете плюс совпадение свойств из справочника (например, файт плюс
  файт, сплит-пушер плюс глобальный герой).
- Поздняя игра: насколько винрейт героя растёт на длинных играх (из меты, корзины по длительности) с поправкой из
  справочника.

### 4.3. Пересечение пулов: украсть или забанить

Для каждого героя считаем **срочность**: шанс, что герой уйдёт к нам (наш пик или бан) до следующего хода соперника.
Шанс берётся из нашего распределения пиков (как сейчас для «их вероятных банов»).

- Пик-кража. Бот берёт не самого ценного героя, а того, у кого больше `срочность × ценность для них + ценность для нас`.
  Пример из требований: у них есть игрок на DK и на Techies, у нас на DK играют, на Techies никто. У DK срочность
  высокая, у Techies около нуля, поэтому первым пиком уходит DK, а Techies остаётся на потом.
- Бан. Ценность бана `h` = шанс, что мы возьмём `h` × ценность `h` для нас + насколько `h` мешает их драфту
  (контрит их пики). Спорный герой, которого они не успевают забрать, потому что первым ходит наша сторона, получает
  прибавку. Отсюда пример с DK: когда у соперника не первый пик, бот банит DK.

### 4.4. Последние пики: контрпик

На последних двух пиках соперника вес «преимущество против нашего драфта по линии и по игре» удваивается. Добавляется
прибавка за **неудобного героя**: у героя в справочнике есть отметка, какой ответ на него нужен (например, иллюзии
требуют AoE или клива, Huskar — урона, проходящего сквозь его лечение, Broodmother — массовой зачистки). Если в нашем
драфте такого ответа нет, прибавка большая. Это касается только героев, на которых их игроки реально играют: Meepo,
Broodmother, Huskar, Terrorblade, Phantom Lancer и подобных из справочника.

### 4.5. Разброс

Бот считает лучший ход и берёт случайно из ходов, оценка которых не ниже 90% от лучшего, не больше трёх, с весом по
оценке. Случайность от зерна из адреса.

## 5. Позиции

### 5.1. Как сайт расставляет позиции

- Наша команда и прогноз по сопернику: как сейчас, распределение «герой → игрок» по статистике игроков (`assign()`),
  у флекс-героев (WR, DK, Dawnbreaker и т. п.) позиция берётся по игроку, который на нём играет.
- План бота: в конце драфта бот перебирает расстановки своих пяти героев по своим пяти игрокам и берёт лучшую по сумме
  «комфорт игрока на герое на этой позиции + линия против нашей расстановки». Если она отличается от того, что
  предсказывала статистика, это **свап**: в итоге он отмечен, например «обман: Windranger ушла с керри в мид, на керри
  взят Phantom Lancer».
- Нашу расстановку бот знает только по статистике, наших ручных правок он не видит: в жизни соперник их тоже не знает.

### 5.2. Ручная правка и пересчёт

| Когда | Что правится | Что пересчитывается |
|---|---|---|
| Во время драфта, наша команда | Позиция героя в выпадающем списке у нашего героя | Сразу: наши советы, лейнеры, оценка линий в подсказках. Прошлые ходы бота не меняются. Будущие ходы бота нашу правку не учитывают (см. 5.1) |
| Во время драфта, соперник | Позиция героя соперника в прогнозе | Сразу: наши советы против их лейнеров. Скрытый план бота не меняется |
| После конца драфта, обе команды | Любая позиция у любого героя | Сразу пересчитывается вся оценка драфта (раздел 6). Ходы не меняются |

Две позиции у одного игрока не допускаются: при выборе занятой позиции герои меняются местами. Правка сбрасывается
кнопкой «как предсказал сайт». Пересчёт идёт тем же запросом, что и сейчас при каждом ходе (меньше секунды), с
задержкой 150 мс после последней правки.

## 6. Оценка после драфта

Для каждого раздела: кто сильнее, насколько (слабо / заметно / сильно) и одна-две причины с именами героев.

1. **Линии.** Лёгкая против сложной, мид, сложная против лёгкой отдельно. Исход линии по STRATZ (победа, ничья,
   поражение, разгромы), объём выборки. Без данных STRATZ по паре героев — оценка по контрпикам меты с пометкой
   «мало данных».
2. **Мид-гейм.** Урон по башням (свойство «пуш» из справочника, пушеры OpenDota, итог линий: кто выиграл линии,
   раньше ломает башни) и Рошан (герои, которые рано и безопасно бьют Рошана).
3. **Лейт-гейм.** Сумма «насколько герой сильнее в длинной игре» по пяти героям: рост винрейта на играх от 45 минут
   из меты и поправка справочника.
4. **Масс-файты.** Массовые ультимейты, контроль по площади, инициация, синергия файтовых свойств.
5. **Сплит-пуш.** Сплит-пушеры, иллюзии и призывы у одной стороны против ответов (глобальные герои, быстрая зачистка,
   ловля) у другой. Кому проще сплитовать.
6. **Кайт.** Дальность и замедления против сближения и ловли. Кому проще кайтить.
7. **Неудобные герои.** Есть ли у каждой стороны ответ на неудобных героев соперника (иллюзии без AoE и т. п.).
8. **Итог.** Кто выиграл драфт. Взвешенная сумма разделов: линии 30%, преимущество по игре (контрпики и синергия
   пятёрок по мете) 25%, мид-гейм 15%, лейт 15%, масс-файты 10%, сплит и кайт 5%. Плюс «кто кого перепикал»:
   сколько контрпиков каждая сторона взяла позже соперника. Свап бота отмечен здесь же.

Веса — первая версия, их можно менять в одном месте (`Scoring`).

## 7. Данные

- `config/hero_traits.yaml` (новый): у каждого героя патча `push`, `roshan`, `teamfight`, `split`, `kite`, `catch`,
  `illusions`, `anti_illusion`, `late` (−2…+2), `awkward` со списком нужных ответов. Агент заполняет по знанию игры,
  тест проверяет, что описаны все герои из `constants/heroes.json` с `cm_enabled`. Ошибки в справочнике пользователь
  правит в файле.
- STRATZ: данные линий за последнюю неделю есть только у героев с id 1–43 (выгрузка прервалась на лимите). Перед
  симуляцией докачать остальных, это обычный `./gradlew run` без изменений кода.
- Поздняя игра: корзины длительности из `lane_roles.json` (данные OpenDota, без фильтра по рангу). Это ограничение
  будет указано на «Методике».
- Урон по башням и Рошан: статистики по героям в данных нет, только справочник и роли OpenDota.

## 8. Проверка

- Тесты бота:
  - кража DK при первом пике, Techies остаётся на потом;
  - бан DK, когда соперник ходит вторым;
  - на последнем пике бот берёт героя с иллюзиями, если у нас нет AoE, и не берёт героя, на котором у них не играют;
  - свап: Windranger уходит в мид, если это выгоднее;
  - одно и то же зерно даёт один и тот же драфт;
  - бот не берёт занятых героев и не ставит двух героев одному игроку.
- Тесты оценки: каждый раздел считается, явно сильный драфт выигрывает, правка позиции меняет итог линий.
- Проверка в браузере `tools/ui-checks/draft_sim.py`:
  - полные 24 хода с ботом за обе стороны первого хода;
  - отмена откатывает ответы бота;
  - галочка «без подсказок» скрывает советы;
  - правка позиции после конца пересчитывает оценку;
  - обновление страницы сохраняет драфт.

## 9. План работ (по коммиту на шаг)

1. Справочник `hero_traits.yaml`, загрузка и тест полноты.
2. Докачать линию STRATZ по всем героям (только данные).
3. `DraftBot` в `dota.analysis`: кандидаты, срочность, кража и бан, контрпик на последних пиках, разброс по зерну,
   план позиций и свап. Тесты бота.
4. `DraftEvaluation`: разделы 1–8, тесты.
5. API: `POST /api/sim/move` (ход бота по состоянию и зерну), оценка в ответе `/api/draft` при законченной симуляции
   с учётом ручных позиций.
6. Интерфейс: переключатель режима, автоходы бота, отмена с откатом, «без подсказок», выпадающие позиции, раскрытие
   плана бота и панель оценки.
7. Проверка в браузере, «Методика» (как считает бот и оценка), README, план и журнал.
