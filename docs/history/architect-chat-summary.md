# Чат-напарник: выжимка обсуждений

**Период:** 4–15 октября 2026
**Чат:** Claude, мой основной чат-напарник по проекту

## Как устроена работа с ИИ

Проект я веду в нескольких чатах, у каждого своя роль:

| Роль | Где | Что делает |
|---|---|---|
| Напарник (этот чат) | Claude | Обсуждаем решения, критикуем идеи, готовим промпты для других агентов, разбираем их результаты |
| Обсуждение идеи и критика | Отдельный чат Claude | Ресёрч аналогов, рисков, стека, спецификация. См. [2026-10-08-idea-and-analogs-chat.md](2026-10-08-idea-and-analogs-chat.md) |
| Исполнитель | Claude Code (облако и локальный CLI) | Пишет код, запускает, исправляет |
| Тестировщик-пользователь | Claude в Chrome | Играет роль капитана команды и оценивает инструмент |

Основной текст я надиктовываю голосом. Полные экспорты всех чатов не выкладываю: там много черновиков, повторов и вопросов не по проекту. Здесь собраны только ход обсуждения и решения. Выжимку помог собрать ИИ, я её вычитал. Мои реплики даны пересказом.

## 4 октября. Старт: первая идея проекта

**Что принёс я.** Первая идея: система, которая по логу или Allure-отчёту определяет причину падения автотеста (баг продукта, ошибка теста, окружение, flaky). Golden Set собирается из специально внесённых ошибок.

**Что сказал ИИ.** Указал на три слабых места:

- flaky нельзя определить по одному логу, нужна история прогонов;
- ошибки, которые я вношу сам, получатся чистыми и однозначными, и метрика будет завышена;
- аналоги уже есть (категории Allure, Auto-Analysis в ReportPortal), с ними придётся сравниваться.

И задал вопросы про пользователя: как выглядит утро разбора красных тестов, что пользователь делает после классификации, какая ошибка дороже.

**Что решил я.** Тему оставил на потом (для ВКР и следующего проекта курса).

## 8 октября. Смена идеи: помощник для турнира по Dota 2

**Что принёс я.** Мы с командой играем в любительском турнире. Предложил сделать первый проект полезным для нас: сбор статистики по нашим игрокам и соперникам, прогноз пиков и банов. Принёс архитектуру из другого чата с исследованием (скрипты, SQLite, короткие отчёты, команды Claude Code).

**Что сказал ИИ.**

- Сильные стороны: реальные пользователи, реальный срок, открытые данные.
- В принесённой архитектуре ИИ почти не участвует: данные тянут скрипты, скор считает формула. Преподаватель спросит, где тут ИИ.
- Для «лучшего драфта» нет эталонного ответа, победа не доказывает, что драфт был хорошим. Предложил задачу с известным ответом: **прогноз пиков соперника** по истории до даты D и сравнение с тем, что он реально взял после. Метрика hit@5, сравнение с частотным baseline.
- Репозиторий по курсу публичный, а разведка соперников в нём будет видна им самим. Код публичный, данные и отчёты в `.gitignore`.
- Исследование советовало Python, а я на нём не пишу. ИИ сказал, что ревьюить код агента на незнакомом языке трудно.

**Где я спорил.** Я хотел использовать этот чат как «скрытого помощника», чтобы черновые вопросы не попадали в историю. ИИ возразил: курс оценивает именно работу с ИИ, и прятать архитектурные решения значит прятать то, что оценивают. Сошлись на компромиссе: решения и выжимки в репозитории, черновики нет. Этот файл как раз результат.

**Что решил я.** Первый проект делаю про турнир. Язык Kotlin (позже поменял на Java, см. 10 октября).

## 8 октября. Разбор результатов ресёрча и идея веб-приложения

**Что принёс я.** Ответ другого чата с аналогами и рисками. Свою идею: веб-приложение с UI, бэкендом, базой и чатом на Claude, чтобы во время пика спросить, например, топ-5 героев их хардлейнера. Считал, что безопасность не нужна, раз пользуемся только мы.

**Что сказал ИИ.**

- Подписка на Claude и API для своего приложения оплачиваются отдельно, нужен ключ из Console с лимитом расходов.
- Архитектура: одно ядро с функциями (топ героев игрока, прогноз пиков, матчапы), к нему REST для UI, инструменты для чата и позже MCP. Модель не читает сырые JSON, а вызывает функции и получает несколько строк из базы.
- **Не согласился с «безопасность не нужна».** Сервер в открытом интернете, за ним ключ, который тратит деньги. Хватит одного пароля на вход и ключа в переменной окружения.
- **Чат во время драфта почти бесполезен.** В Captains Mode на пик около 30 секунд, напечатать и прочитать не успеешь. Ценность в подготовке до матча.
- Позиции соперников лучше не требовать на входе, а определять по данным о линии.

**Где я ошибся.** Думал, что кредит облачных сессий Claude Code можно использовать как API-ключ для приложения. ИИ по описанию на экране показал, что кредит идёт только на облачные сессии. Зато им удобно платить за разработку в облаке.

**Что решил я.** Здесь только обсуждаем и проверяем, детали инструментов обсуждаю в отдельном чате. ИИ собрал список новых фактов, которых у того чата не было (профили открыты по регламенту, ID матчей публикуются на сайте лиги, замены), и посоветовал задавать вопросы по частям, чтобы в истории было видно, как менялись решения.

## 10 октября. Первый шаг реализации: выгрузка данных

**Что принёс я.** Хочу начать с малого: скрипты, которые выкачивают данные игроков в JSON, без бэкенда и UI. Потом посмотреть, как Claude Code отвечает по этим данным и каких героев выдаёт.

**Что сделал ИИ.**

- Проверил лимиты OpenDota по актуальным источникам и **нашёл расхождение**: в блоге OpenDota 2018 года 50 000 вызовов в месяц, а более свежие описания говорят примерно о 2000 в день. Официальная страница не читается без JavaScript. Решение: исходить из худшего варианта и смотреть остаток лимита в заголовках ответа. Эта же устаревшая цифра была в обоих ответах другого чата.
- Предложил, какие эндпоинты качать и как разложить данные по папкам.
- Предложил эксперимент: сначала эталонный подсчёт скриптом, потом тот же вопрос Claude Code по сырым файлам, потом сравнение. И заранее перечислил, где Claude скорее всего ошибётся: прочитает большой файл не целиком, подставит имена героев по памяти, посчитает Turbo без инструкции.
- Проверил через API, что мой профиль открыт и данные отдаются. Предложил сверять ответы агента с Dotabuff как с независимым эталоном.

**Промпт для Claude Code, версия 1.** ИИ написал промпт на Kotlin: выгрузка, эталонный отчёт «топ-5 героев за N дней», фильтры (без Turbo, без матчей с ливерами), тесты на фикстурах, список того, что не делать.

**Где ИИ был недостаточно хорош (я поправил).**

- Перешёл на Java: её я знаю лучше.
- Промпт был перегружен. Агенту в новом чате незачем перечислять, чего не делать (Spring, база, UI), он этого и не планировал.
- Считать отчёты сразу не нужно. Задача шага только собрать все данные как есть, фильтровать и считать по запросу. Игроки, которые почти не играли последние 30 дней, иначе потеряются.
- **Turbo выкидывать нельзя.** Многие играют только Turbo, и это всё равно показывает пул героев. Исключать нужно только Ability Draft. ИИ исходил из общего правила «Turbo это развлечение» и не учёл, как реально играют на любительском уровне.
- Матчи с ливерами отдельно фильтровать незачем, их мало.

ИИ согласился и переписал промпт: стек Java, выгрузка всех матчей за всё время с максимумом полей, справочники героев и режимов, пауза между запросами, повтор при 429, кэш.

## 15 октября. Оформление истории работы с ИИ

**Что принёс я.** Комментарий преподавателя к работе однокурсницы: не хватает проверки ценности через виртуальную персону. Попросил разобрать, как вести историю работы с ИИ в репозитории.

**Что сделал ИИ.**

- Разобрал пример: сильное место это сырой экспорт диалога, где видно, как студент спорил с ИИ и принял решение. Слабые места: критика оформлена только ссылкой без выводов, журнал агента без «где ошибся и как проверил», нет портрета пользователя и проверки ценности.
- Предложил структуру `docs/`: выжимки сессий, журнал эпизодов по шести вопросам показа, решения, критика с выводами, проверка ценности.
- Написал промпт для виртуальной персоны: капитан любительской команды, который отвечает честно и не подстраивается под идею. С ней я провёл тест через Claude в Chrome, результаты будут отдельным файлом.
- Подсказал, как выгрузить сессию Claude Code в текст (`/export`).
